- Model وMappers (`src/core/models/timeline.ts`): إجازة، زمنية، تكليف، دورة، كتاب، موقف يومي.
- `TimelineService.buildForEmployee`، فلترة وترتيب وتجميع أسبوعي/يومي/شهري، وعدّاد المصادر.
- `TimelineView`، اختيار تصاعدي/تنازلي، نطاقات التاريخ والبحث، والتنقل للسجل الأصلي.
- `TimelineApiService` ومصدر المعاملات الحقيقي المرتبط بـ`TransactionEmployee`؛ الصلاحيات عبر `PersonnelReadScope` و`TransactionScopeFilter`.
- PostgreSQL `transactions` و`transaction_employees`، soft archive، وعدم وجود جدول Timeline أو مسارات كتابة له.
- الفروق بين التعامل المحلي والـAPI، وتوافق مرشحي المراحل 1–6 مع التصحيح.

## العيوب المكتشفة والإصلاحات
| الخطورة | الخلل | الإصلاح |
|---|---|---|
| متوسط | الأحد ينسب إلى الأسبوع القادم في التجميع ISO؛ الأسبوع عند نهاية ديسمبر قد ينسب للسنة الخطأ | حساب الاثنين بـ`(weekday+6)%7` وسنة الأسبوع من الخميس؛ اختبار حدود 2018/19 و2020/21 |
| متوسط | الواجهة تقبل «الأقدم أولًا» لكن `groupByPeriod` تعيد ترتيب المجموعات دائمًا تنازليًا | وسيط ترتيب `asc/desc` للمجموعة وأحداثها؛ مجموعة «بدون تاريخ» أخيرة |
| متوسط | عند جلب المصدر نفسه مرتين أو تكرار دور المنتسب في كتاب قد يظهر حدث مكرر | تمييز الحادثة بـ`sourceType,sourceId,employeeId`، وحفظ أول قيمة، والإحصاءات من الأحداث الفريدة |
| عالٍ أداءً | API كانت تستدعي `transactions.list({}, scope)` لكل الكتب المرئية **ومرفقاتها** ثم ترمي غير المرتبط بالمنتسب | إضافة `TransactionRepository.listLinkedToEmployee` بقيد SQL `EXISTS` على العلاقة الحقيقية، `deleted_at IS NULL`، و`transactionScopeCondition` في الاستعلام ذاته |
| متوسط | فلتر `dateTo` في الواجهة يختبر `endDate` بينما API يختبر تاريخ بدء الحدث (`date`) | توحيد معناه لتاريخ الحدث الأساسي؛ نهاية الفترة تبقى معلومة معروضة، لا سبباً لاستبعاد الحدث |
| منخفض | بحث الواجهة يتجاهل المسافات عند تقرير الفلترة لكن يبحث بالنص مع المسافات نفسها | `trim().toLowerCase()` بالواجهة والخدمة المشتقة |
| منخفض | تاريخ شكله صحيح لكنه غير موجود تقويمياً يدخل مجموعة يوم/أسبوع مصطنعة | إرساله إلى مجموعة «بدون تاريخ» بعد تحقق تاريخ حقيقي |

## ما كان صحيحاً ولم يُغيَّر
- Timeline لا جدول له ولا واجهات POST/PATCH/DELETE؛ القراءات مشتقة من الجداول الأصلية كل مرة.
- لا مطابقة نصية بالاسم للكتب في API؛ الرابط `transaction_employees` هو مصدر الحقيقة.
- `personnelScope` يرفض الدخول إلى ملف منتسب غير مخوّل (404)، و`scope` يقيّد الكتب الظاهرة داخل SQL؛ الموقف اليومي إداري فلا يظهر لمستخدم employee.
- أعداد `countsBySource` و`totalCount` تقيس جميع المصادر **قبل فلاتر العرض والحد**، بعد إزالة التكرار فقط، كما ينص عقد Phase7.
- أحداث `appointment` و`transfer` محجوزة للنموذج ولا تُخترع لها سجلات.
