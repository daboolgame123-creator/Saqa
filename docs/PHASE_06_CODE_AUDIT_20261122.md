## الحدود البرمجية التي تمت مراجعتها
- `DailySituationRecord` كيان منفصل عن `Transaction`، يرتبط بالمنتسب عبر `employeeId` ويقبل رابطاً اختيارياً واحداً لسجل إداري.
- إدارة الاستمارات الموروثة ذات الأقسام الستة والتحويل إلى سجلات مستقلة دون اختراع هوية عند غموض الاسم.
- REST `/api/daily-situations`، خدمة المجال، نموذج DTO، PostgreSQL، قيود FK، وعمليات `POST/PATCH/GET`.
- فرض صلاحيات القراءة الإدارية فقط (admin/director) ورفض employee، وعدم إنشاء مسار DELETE لقيود رسمية.
- العرض داخل `DailySituationsView`: فلترة المنتسب بالتطابق الصحيح، والقيود بلا معاملة، إحصاء الأسماء والساعات والإجازات.

## العيوب المثبتة والإصلاح
| الأولوية | السبب | الإصلاح |
|---|---|---|
| عالٍ | `relatedRecord` كان يُقبل كائنًا ناقصًا أو بحقوق إضافية؛ قد يُفقد الرابط عند التخزين | فرض `kind` و`id` معاً، منع حقول إضافية، والتحقق من UUID |
| عالٍ | `PATCH` العام يسمح بنقل `employeeId` بين منتسبين | حظر ذلك في Validator وDTO والمستودع والنسخة المحلية |
| عالٍ | FK المرتبط بإجازة/زمنية/تكليف/دورة يؤكد وجود السجل لا صحة مالكه | مقارنة `employee_id` بالسجل المستقل قبل الكتابة؛ 404 للمفقود و409 لعدم التطابق |
| عالٍ | `relatedSetClause` يعيد استخدام أرقام معاملات SQL من 1 عند تعديل الملاحظة والرابط معاً | مراعاة `parameterOffset` لكل رابط مركّب |
| متوسط | أسماء الموقف القديمة قد تتحول لهوية منتسب بسبب تشابه جزئي | اسم كامل مطبّع ومميز فقط، والحفاظ على النص غير المحوّل |
| عالٍ | القيود المستقلة بدون كتاب لا تظهر في سجل الموقف أو الساعات/الإجازات | عرضها كقيود مستقلة، في القائمة والفلترة والسجل، دون اختراع رقم كتاب أو رابط طباعة |
| متوسط | فلترة المنتسب في عرض الموقف تستخدم `isEmployeeMatch` الجزئي حتى لو كان الموقف يخص آخر | حصر التصفية بالسجل `employeeId` ثم اسم موروث كامل وفريد وغير محوّل مسبقاً |

## ضمانات مهمة
- لم يُغيَّر تصنيف الموقف إلى معاملة، ولم يُخترع كتاب جديد للقيد المستقل؛ مجرد عرض السجل الموجود.
- تظل السجلات القديمة التي لم تُحل هويتها في طبقة الإرث للنظر البشري؛ لا إنشاء رابط تلقائي غامض.
- `relatedRecord.kind=transaction` لا يُفرض عليه مالك واحد لأن الكتاب متعدد المنتسبين؛ PostgreSQL يتحقق من FK. الأنواع الشخصية الأربعة فقط لها شرط المالك.
- لا حذف للسجلات، لا ترحيل قاعدة بيانات، لا لمس لحسابات أو ملفات المستخدم.
- جميع اختبارات API تعتمد PostgreSQL اصطناعية معزولة؛ لا اتصال بـ`alsqaya_staging`.
