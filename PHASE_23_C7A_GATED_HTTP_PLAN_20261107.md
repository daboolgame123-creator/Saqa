# Phase 23 — C7a plan-first detached HTTP candidate (2026-11-07)

**Base:** PR #35 `86550b7b21395b77d19104d43c31fc7dc0c9dc70` (30/30 full CI SUCCESS).  
**Depends on:** Issue #36 release NO-GO; no formal independent approval yet.  
**Scope:** internal candidate HTTP preview + Excel export + approved-config-only Docker PDF, real server-side filter validation and role context, **all permanently downstream of existing HTTP 503 guard**.

## Analysis before implementation
- `reportRoutes.ts` currently returns 503 for every path and method, including `/export`, **before** its historical preview handler.
- `reportQuery` already normalizes/validates `reportType`, dates, document dates, status, type and unsupported source/section fields. A separated `format` query field for export must be validated separately rather than leaking to reportQuery or the SQL.
- `reportController` already derives access from trusted `req.auth`, not query input.
- `ReportApiService.export()` uses exactly the `run()` authorized rows and creates safe Excel exports. Legacy PDFKit is not operationally approved; candidate PDF **must not** fall back to PDFKit. Only `exportManagedDockerPdf` with an explicitly injected trusted, immutable image digest config may be considered later, and it remains unavailable by default.
- `src/components/views/ReportsView.tsx` is intentionally a nonofficial catalog and cannot display fake statistics or initiate an HTTP report while the gate is closed.

## Planned implementation (strict dependency order)
1. Build a detached `createReportCandidateRouter(pdfConfig?)` with validated `GET /` preview and `GET /export?format=excel|pdf`. PDF must 503 if no independently approved config **before** data access.
2. Mount this candidate **only after** the existing unconditional 503 responder within `createReportRouter`, preserving all production paths as 503. No environment toggle. Never change global authentication or role permissions.
3. The export response must always be a real bounded binary buffer, generated by the authorized service from the same normalized filters, with `no-store`, `nosniff`, restricted `Content-Disposition` filename and known MIME. Reject unknown formats/filters and malformed output; no request-selected image/executable.
4. Add self-contained local HTTP tests with a disposable mock service, verifying session-derived scopes, unsupported filters, validation-before-SQL, nonprivileged denial, XLSX summary/details, PDF fail-closed, and **production** 503 for every report/export method. Retain C5 real PostgreSQL/Docker parity proof.
5. Run full C2/C4/C5 CI on **exact candidate commit** plus regular server regressions. Do not mark passed before GitHub reports success. Open stacked **draft** PR based on #35; no merge.
6. A separately reviewed second C7 task must implement and visually accept the official frontend behind this gate. It is not complete merely because an unmounted candidate exists.

## Explicit release hold
Never enable HTTP reports, switch to unisolated PDFKit for official exports, ship an unpinned image or claim institutional-host approval from CI. Independent role/filter security review, font/image provenance, host watchdog, Arabic print and formal merge permission remain blockers tracked in Issue #36.
